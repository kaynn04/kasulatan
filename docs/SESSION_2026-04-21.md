## Concepts Learned

### 1. **Prisma Transactions (`$transaction`)**
- Groups multiple database operations into a single atomic unit
- Either all operations succeed or all are rolled back
- Prevents incomplete data (e.g., Agreement without Parties)

**Syntax:**
```tsx
await prisma.$transaction(async (tx) => {
    // tx is the transaction client provided by Prisma
    await tx.model.create({ ... });
    await tx.anotherModel.createMany({ ... });
});
```

### 2. **Function Parameters**
- Variables in function definitions that receive values when the function is called
- In arrow functions: `(paramName) => { ... }`
- The caller (or method) decides what value fills the parameter
- Example: `tx` in `async (tx) => { ... }` is filled by Prisma with a transaction client

### 3. **Prisma Relations (`include`)**
- `include: { parties: true }` tells Prisma to fetch related records
- Uses the relations defined in `schema.prisma`
- Returns nested data structure (agreement with parties array)

### 4. **Why We Store Results in Variables**
```tsx
const agreement = await tx.agreement.create({ ... });
// Need agreement.id to link the parties
```
- Database auto-generates the `id` field
- We need that `id` to create related records (foreign key)
